# Create-ClearGoal

一个 Create 附属模组，为 Create 的加工机械（工作盆、动力锯等）引入**配方过滤器**物品。

## 功能

**大宗工厂仪表（Bulk Factory Gauge）** 是**工厂仪表**（Create 的 `factory_gauge`）的扩展方块，行为完全一致（仓储监控、打包机补货、物流网络连接、红石输出、显示链接、扳手交互），区别仅在目标数量设置：

- 长按右键弹出的目标数量滑动条从原版的 2 行（0-100 个/组，线性）扩展为 **4 行（全部按组）**：
  - **0-32 组**：线性刻度
  - **32-256 组**：以 64、128 分割（每小段线性）
  - **256-2048 组**：以 512、1024 分割（每小段线性）
  - **2048-16384 组**：以 4096、8192 分割（每小段线性）
- 低量程线性、高量程分段线性（每段内线性插值），值始终为整数（不出现小数）；行数据与条宽由配置计算，不硬编码
- “组”按物品自身堆叠上限换算（与 Create 原版一致：需求 = 组数 × maxStackSize）
- 外观与原版一致：面板正面渲染记录物品图标，右上角状态灯（红/绿）与连接路径全部沿用 Create 的渲染
- 模型/贴图沿用 Create 原版工厂仪表（面板渲染与物品图标一致），物品同样需要先“调谐”（手持仓储链接站右键）再放置

## 产品返回站（初版）

**产品返回站** 是贴在打包机上的新方块，使打包机进入“返回阶段”（黄色状态条）。它需要先像工厂仪表一样通过点击已有网络调谐频率，再通过 GUI 设置：

- 原料输入端地址（检查网络中承诺的来源地址）
- 产品输出端地址（打包后发送到的地址）

当前为初版：模型/贴图暂用仓储链接站（Stock Link），GUI 使用已有玩家背包贴图占位，**需要自制美术资产**。产品返回站使用**独立承诺队列**（按物品、按数量升序的优先队列），只统计放置后且匹配“原料输入端地址”的工厂仪表承诺；发送货物不影响 Create 原版承诺系统，仅在工厂仪表创建承诺、承诺完成、承诺手动取消三个交叉点与 Create 原系统交互。

## 合成配方

- **配方过滤器**：`[红石粉] [工作台] [红石粉]`（一行，类似 Create 列表过滤器但替换材料）
- **大宗工厂仪表**：`工厂仪表 + 磨制玫瑰石英`（无序合成）

**配方过滤器（Recipe Filter）** 是一种可放入 Create 机械过滤槽的物品，用于按"记录的配方"限制机器的配方选择：

- **记录配方**：手持过滤器右键打开编辑界面——
  - 每页一行配方（滚轮切换、可改名、可删除），最多 9 条
  - 3×3 输入槽 + 3 输出槽（可拖拽物品或从 JEI / EMI / REI 导入）
  - JEI / EMI / REI 导入时会同时保存流体的输入/输出；带 `recipeId` 的导入配方在运行时按原配方语义匹配，因此 Tag 输入、流体配方和 4 种物品输出不会退化
  - 在 JEI / EMI / REI 的配方界面点击导入按钮可直接把配方导入过滤器
- **三种过滤模式**（过滤器级，不随配方切换）：
  - **阻止记录的配方**（Block）：剔除产物匹配记录的候选
  - **只允许记录的配方**（Allow-only）：只保留产物匹配的候选
  - 导入条目在 Block / Allow-only 下按 `recipeId` **或**产物匹配（该条目的 Exact / Contains）双重判定：原配方始终命中（保持 Tag 输入、流体和 4 物品输出语义），其它候选按产物匹配判定
  - **按输入锁定**（Lock on input，默认）：机器输入（物品与流体）命中记录配方的输入时，锁定为记录配方；否则放行所有。LOCK 的触发**只判断输入类型是否命中**（只比较物品种类/流体种类，不比较数量，也不含热量等运行条件）；一旦输入命中，配方可用则运行它，不可用（热量/材料不足、配方被移除等）则机器**停止加工**，绝不改做其它配方
- **两种产物匹配方式**（配方级，随配方切换）：
  - **精确匹配**（Exact）：产物集合完全一致
  - **包含匹配**（Contains）：记录产物是候选产物的子集
- **即时生效**：连续处理（同配方一批接一批）时，装/移/编辑过滤器都会在**本批结束后立即**按新过滤器重新选择配方

### 支持场景

- 原料 A 可加工为 B 或 C 时，锁定"输入 A → 只产出 B"
- 其他输入（D、E）不受影响，按 Create 原逻辑选择配方
- 可在**工作盆**（辊压机、动力搅拌器）与**动力锯**的过滤槽中使用
- 配方过滤器也可以嵌套在 Create 的**列表过滤器**中使用；`RecipeFilterHelper` 会递归找到它并应用配方锁定
- 手动填槽目前只支持物品输入/输出；从 JEI / EMI / REI 导入的配方会额外保留流体输入/输出并按原配方语义匹配
- 大宗工厂仪表与工厂仪表共用同一套物流网络与仓储逻辑，两者可混用；目标数量以各自面板的设置为准

## 环境要求

- Minecraft **1.21.1**
- NeoForge **21.1.248**（Java 21；兼容范围放宽到 21.1.x）
- Create **6.0.11-295**（依赖声明；实测兼容 **6.0.10**）
- JEI / EMI / REI（可选，任一安装即可获得配方导入与物品拖拽；Create 配方在 EMI/REI 中能否显示取决于对应的兼容插件）

## 构建

```bash
gradlew.bat build
```

构建产物位于 `build/libs/`，放入游戏 `mods` 目录即可。

## 使用

1. 获得**配方过滤器**（创造标签页 / 物品栏）
2. 手持右键打开编辑界面
3. 方式一：从 JEI / EMI / REI 侧栏拖拽物品填入输入/输出槽；方式二：在 JEI / EMI / REI 配方界面点击导入按钮
4. 选择过滤模式与产物匹配方式
5. 放入**工作盆**或**动力锯**的过滤槽
6. 机器按记录配方工作；输入与记录不一致时恢复正常配方选择

## 技术说明

- 锁定逻辑通过 Mixin 在 Create 的配方选择层实现（`BasinOperatingBlockEntity.getMatchingRecipes` / `SawBlockEntity.getRecipes`），不会拦截普通物品流动
- 过滤器测试方法（`test`）恒为通过——它是配方选择层的"标记"，而非物品过滤
- 全新未配置的过滤器也会被强制包装为 `RecipeFilterItemStack`，不会被 Create 当作普通物品过滤器
- 嵌套在列表过滤器中时，由 `RecipeFilterHelper` 递归查找并应用其中的配方过滤器；列表过滤器自身的 allow/deny 规则仍按 Create 原生行为执行
- JEI / EMI / REI 适配：JEI 覆盖全部 Create 配方类型导入 + 过滤槽物品拖拽（ghost ingredient）；EMI（fill 按钮 + 侧栏拖拽）与 REI（transfer 按钮 + 拖拽）提供同等能力，均走同一 `RecipeFilterImportPacket` 服务端回写
- 导入的配方在 BLOCK / ALLOW_ONLY 下按 `recipeId` **或**产物匹配（Exact / Contains）双重判定；LOCK 的输入命中判定只检查物品/流体**类型**是否命中（不比较数量，也不含热量与输出空间检查）——运行与否（含停摆）由配方可用性决定，避免"热量不足 → 误判未命中 → 放行其它配方"
